# 使用条款 - Xtra Computing 服务器

*最后更新：2026-08-14*

> 本文为英文版 [README.md](README.md) 的中文译本，仅供参考。如中英文表述存在歧义或冲突，以英文版为准。

**简介**
Xtra Computing 服务器提供计算资源（GPU、CPU、内存与存储），主要用于支持科研与学术活动。用户必须遵守本文所列的各项规定，以确保资源分配的公平性并维护良好的计算环境。

> [!IMPORTANT]
> 资源仅供 Xtra Computing 组使用。

> [!WARNING]
> 任何滥用行为都可能导致您的计算任务被终止。

## 账号

### 账号申请

用户须通过指定的注册表单申请：https://forms.gle/Wf8qbNeuSPS2ia8u6

账号有效期以用户注册时填写的到期日期为准，并须经管理员确认。

账号获批后，请阅读[新人使用指南](docs/getting-started.zh-CN.md)，了解开通流程、
服务器地址与基本资源使用规则。

### 账号管理

| 事件 | 处理方式 | 说明 |
|------|----------|------|
| 账号到期 | 账号冻结 | 无法登录。请在 6 个月内联系管理员解冻。 |
| 到期后 6 个月 | 删除账号 | 数据临时保存在冷存储[^1]中；不保证完整性。 |
| 到期后 12 个月 | 删除数据 | 文件被永久删除，无法恢复。 |

[^1]: 冷存储是一类面向低频访问数据的存储方式。由于数据存入和取出冷存储耗时较长，它主要用于归档或备份，而不适用于需要频繁访问的数据。

所有通知与告警仅通过您注册时填写的邮箱发送。

> [!CAUTION]
> 如果您的账号持续处于到期状态，您的数据可能在 6 个月后被移除，并在 12 个月后被永久删除。

**解冻账号**
账号被冻结后如需恢复使用，请联系管理员。恢复申请通常在 1-2 个工作日内处理。

### 离开研究组

当用户离开 Xtra Computing 研究组或 NUS 时，其对 Xtra Computing 服务器的访问权限将**立即终止**。

> [!CAUTION]
> **请在离开前备份好自己的数据。** 访问权限自离开之日起终止。我们不会在账号到期前发出任何提醒，事后也不提供任何用于取回数据的宽限期。

离开时：

- 用户账号将在离开日期当天被冻结，届时无法再登录。
- 在权限终止前，我们不会发送任何事先通知、提醒或到期预警。在离开日期之前迁移数据和计算环境，完全是用户自己的责任。
- 服务器资源不得用于个人事务、外部项目、就职工作，或与 Xtra Computing 研究组无关的研究。

账号冻结后，账号内剩余数据按[账号管理](#账号管理)一节所述的标准数据保留规则处理：6 个月后移入冷存储，12 个月后永久删除。冷存储中的数据不保证完整性，取回请求也可能被拒绝。

例外情况仅按个案批准，并可能因安全、运维或 SoC IT 的要求随时被撤销。

## 可接受使用与安全

用户不得：

- 共享账号、密码、SSH 密钥、访问令牌或任何其他凭据。
- 挖掘加密货币，或将服务器资源用于相关活动。
- 进行未经授权的攻击、漏洞扫描、网络扫描、恶意软件活动，或试图干扰系统及其他用户。
- 绕过、规避、禁用或干扰资源限制、监控、访问控制或策略执行机制。
- 存储、传播或处理违法内容，或侵犯软件许可、著作权及其他知识产权。
- 在未获得管理员事先批准，以及未取得适用机构政策所要求的其他批准的情况下，处理敏感、受监管、机密或涉及研究受试者的数据。

以上列举并不穷尽。一经发现上述任何行为，相关账号将被永久封禁。此类违规不适用下文所述的累进处罚机制。

## 磁盘

### **磁盘空间分配**

| 用户类别 | `home` 磁盘配额 |
|----------|-----------------|
| 博士生 | 512 GiB |
| 其他 | 256 GiB |

可通过邮件向管理员申请额外磁盘空间，管理员将根据项目理由与资源可用情况进行评估。

如需存放大型数据集，请联系管理员。数据集托管不计入您的配额。

### **数据完整性**

数据完整性**不作保证**。用户必须定期备份，建议每周备份一次，关键数据建议更高频率备份。`/shared/hdd` 与 `/shared/ssd` 目录采用 RAIDZ2，可容忍最多两块硬盘故障。RAIDZ2 **不是备份**，也无法防止所有形式的数据丢失。这些共享目录目前没有按用户设置的配额，请合理使用。

> [!IMPORTANT]
> 备份责任由用户承担。请始终为关键工作保留可恢复的检查点。

### **隐私**

管理员可能收集并查看必要的访问、安全、审计、系统及资源使用日志与指标，用于运维、安全、容量规划、事件响应与策略执行。在调查事件、异常资源使用、安全问题或疑似违规行为时，管理员也可能查看文件。使用本服务器即表示用户同意上述监控与审查。

**请勿**存放私人或敏感文件（例如个人照片、视频、机密文档）。

### **磁盘使用统计**

磁盘使用量按月统计（GB/月），覆盖所有服务器，并按用户分别归属。使用量较高的用户可能会被联系，要求减少磁盘占用。

## GPU

### 默认配额

我们希望所有用户都能平等、便捷地使用 GPU 资源。系统设计力求在保证用户间公平的前提下尽量减少限制。

| 用户类别 | 无需申请即可使用的 GPU 数 |
|----------|---------------------------|
| all_user | 2 块 GPU 自由使用 |

用户可在配额内自由使用 GPU；当有额外 GPU 空闲且未被他人使用时，也可超出配额使用。

GPU 配额指的是无需申请即可使用的标准分配上限，并不构成对 GPU 可用性、访问连续性、任务完成或性能的保证。

如有高强度计算任务，建议使用 [HACC 集群](https://hacc.xtra.science) 或 [SoC 集群](https://dochub.comp.nus.edu.sg/cf/guides/compute-cluster/access)，它们更适合高性能计算需求。使用 HACC 集群需填写 [HACC 集群账号申请表](https://forms.gle/fvfPgJypd1sSWzHm8)。请注意，SoC 集群的文档需在 SoC 内网环境下才能访问。

### 超额使用 GPU

**您可以在不申请的情况下使用超过 2 块 GPU。** 但超出配额的 GPU 使用属于机会性使用，可能被抢占：

- 配额内的 GPU 任务也不保证持续可用或不被中断。
- 超出配额的 GPU 属于**尽力而为**性质。当其他用户需要 GPU 以填满其自身配额时，您的超额任务可能被终止以释放资源。
- 任何 GPU 任务也可能因维护、故障、安全事件、策略执行或其他运维需要而被中断或终止。
- 管理员可能会在终止前尝试通知受影响用户，但不保证提前通知。
- 运行超额 GPU 任务的用户应实现检查点机制，以尽量减少因抢占造成的进度损失。

> [!IMPORTANT]
> 超出 GPU 配额的任务可能在任何时候被终止，以保障所有用户的公平使用。请务必保存检查点。

### 合理使用

为确保共享 GPU 基础设施得到公平、高效的利用，我们即刻起实施以下资源管理政策：

#### 自动终止政策

任何满足以下条件的进程：
1. 占用大量 GPU 显存，且
2. GPU 利用率持续低于 1% 达 10 分钟

可能被系统自动终止。

> [!WARNING]
> 低利用率、高显存占用的 GPU 任务可能被自动终止。

#### 用户责任

用户须自行负责监控其任务。因本政策下的自动终止而造成的任何进度、数据或运行时间损失，由任务所有者承担。

请确保您的脚本：
1. 空闲时不占用 GPU 显存
2. 不活动时正确释放资源
3. 避免长时间处于零利用率状态

> [!CAUTION]
> 因策略触发的终止而导致的进度或数据损失由用户自行承担。

#### 临时例外

管理员可根据具体申请情况逐案批准临时例外。如果您的工作负载确实需要在低利用率或零利用率下常驻 GPU 显存，请事先联系管理员并说明理由。

感谢您的配合。

## CPU 与内存

每位用户在每个节点上受 **500 GiB 内存上限**约束，通常通过 systemd `user-.slice` cgroup 强制执行。超过该上限的进程可能在用户所属 slice 内被 OOM 杀死。执行行为与进程隔离不作保证。如有正当理由，可申请更高上限。

CPU 使用默认不设上限。在单台机器上，如果某用户的进程持续占用相当于该机器逻辑 CPU 核心数 50% 以上的 CPU 资源超过连续 8 小时，将在不事先通知的情况下对该用户施加该机器上的 CPU 配额。该配额将用户在该机器上的 CPU 总使用量限制为其逻辑 CPU 核心数的四分之一（1/4）。配额一经施加将永久有效。除内存上限外，内存使用不另设限制；但过度占用内存并对他人造成负面影响可能导致处罚。

过度使用依据其对系统稳定性的影响判定：

- 内存不足（OOM）错误导致其他用户无法使用服务器（例如无法 SSH 登录）。
- 任何需要管理员介入才能恢复正常运行的行为。

| 违规次数 | 处理方式 |
|----------|----------|
| 第 1 次 | 通知 |
| 第 2 次 | 警告 |
| 第 3 次 | 冻结账号 2 天 |
| 第 4 次 | 冻结账号 2 周 |
| 第 5 次 | 永久封禁所有基础设施 |

违规计数自首次违规之日起计算，并以 3 个月滚动窗口进行统计。窗口之外的违规不计入。*（暂行规定，可能修订。）*

管理员可依据其运维判断认定违规行为并施加处罚，无需提供正式证据或走举证程序。受影响用户可联系管理员申诉。对于本条款的解释，以及违规、例外、执行措施与申诉的处理结果，管理员拥有唯一且最终的决定权。

### Docker 引发的违规

通过 Docker 容器造成的滥用——包括但不限于引发 OOM 错误或不当占用 GPU——适用其自身的累进机制，重点针对 Docker 权限：

| 违规次数 | 处理方式 |
|----------|----------|
| 第 1 次 | 通知 |
| 第 2 次 | 警告 |
| 第 3 次 | 永久撤销 Docker 权限；账号被标记 |

同样适用 3 个月滚动窗口。*（暂行规定，可能修订。）*
