# 管理员责任边界

> 本文为 [admin-liability.md](admin-liability.md) 的中文译本，仅供参考。如中英文表述存在歧义或冲突，以英文版为准。

本页明确 Xtra Computing 服务器管理员的运维职责边界。所有管理活动与支持均以尽力而为的方式提供，不构成任何承诺、保证、担保或服务水平承诺。

## 管理员负责的事项

- 以合理、尽力而为的方式维护服务器运行与核心基础设施。
- 为共享环境施加合理的安全与访问控制。
- 在需要时对服务器进行安全、合规与运维完整性审计。
- 执行已公布的资源政策（GPU、CPU、内存、磁盘与账号规则）。
- 响应影响多个用户或平台稳定性的服务事件。
- 通过官方渠道沟通重大政策或运维变更。

## 管理员不负责的事项

- 用户之间的资源协调。用户应自行沟通并协调共享资源的使用。
- 用户代码质量、训练逻辑、实验设计或运行时正确性。
- 调试用户代码、模型流水线或自定义脚本。
- 因用户操作、脚本缺陷、误删除或不安全工作流导致的数据丢失。
- 因策略执行（包括自动终止规则）导致的任务中断。
- 恢复超出现有备份/保留窗口的文件。
- 保证每一种工作负载、模型或软件栈的性能。

## 用户侧责任

- 主动监控任务，并核实 GPU/CPU 利用率是否符合预期。
- 为所有关键工作实现检查点与备份。
- 任务空闲或不再需要时及时释放资源。
- 保持环境与依赖可复现、可维护。
- 对需要政策例外的特殊工作负载，提前联系管理员。

## 事件处理边界

- 当系统稳定性、公平性或安全性受到影响时，管理员可以介入。
- 介入措施可能包括限流、终止任务、限制账号或临时停用。
- 在紧急情况下，可在逐一通知之前先采取保护性措施。

## 支持范围

- 对于账号访问、平台级故障与政策释疑，提供尽力而为的支持。
- 对用户应用、模型流水线或自定义环境的深度调试，默认不在支持范围内。

如果您的情况不明确，请联系管理员，并提供可复现的细节、预期行为以及紧急程度。
